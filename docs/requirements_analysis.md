## 1. 숫자 버튼으로 채널 변경 동작

숫자 키는 **최대 2자리 채널 번호**를 조합한다. 유효 채널은 **0~99**이다.

### 1.1 입력 버퍼 규칙

| 규칙 ID | 설명 | 구현 힌트 |
|---------|------|-----------|
| D-01 | 숫자 키는 `processingCH`에 한 자리씩 누적한다 | `processingCH += digitChar` |
| D-02 | **두 번째 숫자**가 들어오면 **즉시** 해당 2자리 채널로 변경(커밋)한다 | 2자리 도달 시 `setCH` 호출 후 버퍼 초기화 |
| D-03 | **한 자리만** 쌓인 상태에서 **확인(KEY_OK)** 을 누르면 그 한 자리 채널로 변경한다 | `setCH(processingCH)` |
| D-04 | 선행 `0`은 단독 채널 `0`이 아니라 **다음 숫자와 합쳐지거나 무시**된다 | `'0','7'` → `"7"` (아래 시나리오) |
| D-05 | 세 번째 연속 숫자는 **새 입력의 첫 자리**로 간주한다 (이전 커밋 후) | `'1','2','3','4'` → `12` 적용 후 `34` 적용 |

### 1.2 명세 시나리오 (README)

| # | 입력 시퀀스 | 기대 채널 | 메모 |
|---|-------------|-----------|------|
| 1.1 | `1` → `OK` | `1` | 1자리 + 확인 |
| 1.2 | `1` → `2` | `12` | 2자리 즉시 커밋 (확인 불필요) |
| 1.3 | `1` → `2` → `3` → `4` | `12` → `34` | 2자리마다 자동 커밋 |
| 1.4 | `4` → `5` → `6` | `45` (이후 `6`은 버퍼에 대기) | 세 번째 숫자는 단독 대기 상태 |
| 1.5 | `0` → `7` | `7` | 선행 0 처리: `07` → `7` |
| 1.6 | `4`→`5`→`6` 후 `6`+`OK` 또는 `6`+다른숫자 | `6` 또는 `6x` | 대기 중인 `6`을 이어서 확정 |
| 1.7 | `4`→`5`→`6` 후 **숫자·확인 외** 키 | `45` 유지, 버퍼의 `6` **무효화** | 다른 키 = 버퍼 클리어 |

### 1.3 상태 전이 (QA용)

```text
[Idle] --digit--> [1 digit buffered]
[1 digit] --digit--> [commit 2-digit] --> [Idle]
[1 digit] --OK--> [commit 1-digit] --> [Idle]
[2-digit committed] --digit--> [1 digit buffered]  (새 조합 시작)
[Any buffered] --non-digit-non-OK (정책 키)--> [Idle] or invalidate pending only
```

## 2. 버튼 하나만 들어올 때마다 동작

**한 번의 `pushButton` 호출 = 리모컨에서 키 하나 수신**이다. 동시 입력·키 홀드는 범위 밖이다.

### 2.1 키 종류별 단일 입력 반응

| 키 (1회) | 전제 상태 | 동작 | `Tuner` 호출 |
|----------|-----------|------|--------------|
| 숫자 `0`~`9` | 버퍼 비어 있음 | 버퍼에 1자리 적재 | 없음 (또는 2자리 완성 시 `setCH`) |
| 숫자 | 버퍼 1자리 | 2자리 조합 후 **즉시 커밋** | `setCH` |
| `OK` | 버퍼 1자리 | 1자리 채널 커밋 | `setCH` |
| `OK` | 버퍼 비어 있음 | 명세 미기술 → **무시(no-op)** 권장 | 없음 |
| `CH_UP` / `CH_DOWN` | 검색 목록 없음 | 현재 채널 ±1 (경계 래핑) | `getCurrentCH` → 계산 → `setCH` |
| `CH_UP` / `CH_DOWN` | 검색 목록 있음 | 목록 내 이전/다음 | `setCH` |
| `SEARCH` |任意 | `seekCH()` 반복으로 목록 저장 | `seekCH` (N회) |
| `FAV_ADD` | 현재 시청 채널 C | 선호 목록 토글 | `getCurrentCH` (필요 시) |
| `FAV_NEXT` | 선호 목록 비어 있지 않음 | 다음 선호 채널로 이동 | `setCH` |

### 2.2 단일 입력 시 QA 체크리스트

1. 각 테스트는 `pushButton` **정확히 1회** 후 상태·Mock 호출 횟수를 검증한다.
2. 숫자 1회만으로는 **대부분** `setCH`가 호출되지 않아야 한다 (2자리 자동 커밋·`OK` 예외).
3. 업/다운·선호·검색은 **입력 1회당 부수 효과 1회** (목록 갱신, 토글, 한 칸 이동).

## 3. 두 자리 숫자 또는 확인 버튼 시 변경 적용

커밋(실제 `Tuner::setCH` 호출) 트리거는 아래 **둘 중 하나**이다.

| 트리거 | 조건 | 적용 채널 값 | 버퍼 처리 |
|--------|------|--------------|-----------|
| **T-A: 2자리 완성** | 연속 숫자 2개 입력 | `processingCH` (2자) | 커밋 후 `""` 로 초기화 |
| **T-B: 확인** | 버퍼에 1자리만 존재 시 `OK` | `processingCH` (1자) | 커밋 후 초기화 |

### 3.1 커밋하지 않는 경우

| 상황 | 동작 |
|------|------|
| 숫자 0개인 상태에서 `OK` | no-op (권장) |
| 숫자 1개만 있고 아직 `OK`·두 번째 숫자 없음 | **시청 채널 유지**, 버퍼만 유지 |
| 유효하지 않은 조합 (예: 커밋 시 `100`) | `setCH`가 예외 → 컨트롤러는 예외 전파 또는 catch 후 버퍼 초기화 (정책 명시 필요) |

### 3.2 C++ 테스트 패턴 예시

```cpp
// 1자리 + OK
EXPECT_CALL(mockTuner, setCH("1"));
controller.pushButton(remoteKey::KEY_1);
controller.pushButton(remoteKey::KEY_OK);

// 2자리 즉시 커밋 (OK 없음)
EXPECT_CALL(mockTuner, setCH("12"));
controller.pushButton(remoteKey::KEY_1);
controller.pushButton(remoteKey::KEY_2);
```

## 4. 선호 채널 기능 정리

### 4.1 데이터 모델

| 항목 | 설명 |
|------|------|
| 저장소 | 컨트롤러 내부 컨테이너 (예: `std::set<int>` 또는 정렬된 `std::vector<std::string>`) |
| 초기 상태 | 빈 목록 |
| 중복 | 동일 채널 중복 저장 불가 |
| 정렬 | `FAV_NEXT`를 위해 **오름차순** 유지 권장 |

### 4.2 기능 요약

| 기능 | 트리거 | 동작 |
|------|--------|------|
| 선호 추가/삭제 (토글) | `FAV_ADD` (선호채널추가) | 현재 시청 채널 기준 |
| 다음 선호 이동 | `FAV_NEXT` (다음선호채널) | 목록에서 “위 방향” 다음 채널 |

### 4.3 선호 채널이 아닌 경우 / 이미 선호인 경우

| 현재 채널 C | 목록에 C 존재 | `FAV_ADD` 1회 결과 |
|-------------|---------------|-------------------|
| 임의 | 없음 | C **추가** |
| 임의 | 있음 | C **삭제** (토글 off) |

> 시청 중인 채널은 `getCurrentCH()`로 얻는다. 숫자 입력 버퍼(`processingCH`)와 혼동하지 않는다.

## 5. 선호 채널 변경 기능 동작 정리

### 5.1 다음 선호 채널 (`FAV_NEXT`)

**규칙**: 선호 목록에서 **현재 채널값보다 큰 값 중 가장 작은 채널**로 이동. 없으면 **가장 작은 선호 채널로 로테이션**.

| 선호 목록 (오름차순) | 현재 채널 | `FAV_NEXT` 1회 결과 |
|---------------------|-----------|---------------------|
| 1, 4, 12, 56 | 6 | 12 |
| 1, 4, 12, 56 | 56 | 1 (로테이션) |
| 1, 4, 12, 56 | 12 | 56 |
| 1, 4, 12, 56 | 0 | 1 |
| (빈 목록) |任意 | 명세 미기술 → no-op 또는 예외 정책 정의 필요 |

### 5.2 알고리즘 (구현·테스트 공통)

```text
favorites = sorted ascending
current = stoi(getCurrentCH())
next = min { f in favorites | f > current }
if next not exists:
    next = favorites.front()   // wrap
setCH(to_string(next))
```

### 5.3 QA 케이스 매트릭스

| ID | favorites | current | expected after FAV_NEXT |
|----|-----------|---------|-------------------------|
| F-01 | {1,4,12,56} | 6 | 12 |
| F-02 | {1,4,12,56} | 56 | 1 |
| F-03 | {1,4,12,56} | 4 | 12 |
| F-04 | {7} | 7 | 7 (단일 요소 로테이션) |

## 6. 기타 버튼 입력 시 동작 정리

### 6.1 채널 검색 (`SEARCH`)

| 항목 | 내용 |
|------|------|
| 동작 | `seekCH()`를 호출하여 **시청 가능 채널**을 순차 검색·**내부 목록에 저장** |
| 종료 조건 | `seekCH()`가 빈 문자열 반환 시 중단 (또는 더 이상 채널 없음) |
| 이후 영향 | 저장 목록이 있으면 **업/다운은 §6.2** 규칙 적용 |
| QA | `TunerTest::testSeekCh10times`처럼 반복 호출·0~99 범위 검증 |

### 6.2 채널 업/다운 — 검색 목록 **없음**

| 현재 | 키 | 결과 |
|------|-----|------|
| 6 | UP | 7 |
| 6 | DOWN | 5 |
| 99 | UP | 0 |
| 0 | DOWN | 99 |

구현: `next = (current + delta + 100) % 100` 후 `setCH`.

### 6.3 채널 업/다운 — 검색 목록 **있음** (예: 4, 6, 14)

| 현재 | 키 | 결과 | 설명 |
|------|-----|------|------|
| 6 | UP | 14 | 목록에서 현재보다 큰 최소값 |
| 6 | DOWN | 4 | 목록에서 현재보다 작은 최대값 |
| 15 (목록 밖) | UP | 4 | 래핑: 다음이 없으면 목록 **처음** |
| 15 | DOWN | 14 | 래핑: 이전이 없으면 목록 **끝** |

### 6.4 숫자 입력과 충돌하는 “기타 버튼”

| 키 | `processingCH`에 미확정 숫자 있음 | 동작 |
|----|-----------------------------------|------|
| `CH_UP` / `CH_DOWN` | 예 (예: `6` 대기) | **대기 숫자 무효화** 후 업/다운 수행 (README: `4,5,6` 후 기타 버튼 → `6` 무효) |
| `FAV_ADD` / `FAV_NEXT` | 예 | 버퍼 클리어 후 해당 기능 수행 (권장 일관성) |
| `SEARCH` | 예 | 버퍼 클리어 후 검색 시작 |
| `OK` | 0자리 | no-op |

### 6.5 전체 리모컨 키 ↔ 책임 매트릭스

| `remoteKey` (권장명) | 주 기능 | `setCH` | `seekCH` | 내부 상태 변경 |
|---------------------|---------|---------|----------|----------------|
| `KEY_0`~`KEY_9` | 숫자 조합 / 커밋 | 조건부 | — | `processingCH` |
| `KEY_OK` | 1자리 확정 | 조건부 | — | 버퍼 클리어 |
| `KEY_CH_UP` / `KEY_CH_DOWN` | 채널 이동 | 예 | — | 검색/선호 목록 유지 |
| `KEY_SEARCH` | 검색 목록 구축 | — | 반복 | `searchedChannels` |
| `KEY_FAV_ADD` | 선호 토글 | — | — | `favoriteChannels` |
| `KEY_FAV_NEXT` | 다음 선호 | 예 | — | — |
