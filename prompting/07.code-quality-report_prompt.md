## 분석 완료

**`updateQuality()`는 현재 저장소에 없습니다.** 동일한 결합·분기·매직넘버 패턴을 보이는 실질 진입점 **`pushButton()` 및 `TVController` 전반**을 분석했고, 결과는 `docs/code_quality_report.md`에 저장했습니다.

### 핵심 표 (요약)

| 문제점 | 위반 원칙/스멜 | 영향 | 개선 방향 | 우선순위 |
|--------|----------------|------|-----------|----------|
| 한 클래스에 입력·버퍼·선호·검색·3종 네비·로깅 | SRP, God Class | 변경·회귀 범위 과대 | 역할별 타입 분리, 컨트롤러는 위임만 | 4 |
| `pushButton`의 `switch` | OCP | 키 추가마다 수정 | 테이블 기반 핸들러 맵 | 3 |
| search up / fav next / search down의 순환 탐색 3중 복제 | Duplicated Code | 한쪽만 수정 시 불일치 | `findNeighbor()` + `optional` | **1** |
| `(ch±1+100)%100` 대칭 | Duplicated Code | up/down 2곳 수정 | `stepChannel(ch, delta)` | 2 |
| `0`, `99`, `100`, `2`, `-1`, `+99` | Magic Number | 도메인 변경 시 누락 | `constexpr` 상수, `optional` | 2 |

언급하신 **0, 50, 11, 6** 중 **0·99·100·2는 구현 리터럴**, **6·50은 README/테스트 시나리오**, **11은 코드·명세에 없음** (12 또는 99와 혼동 가능)으로 정리했습니다.

### 리팩토링 우선순위 (1~5)

1. **정렬 벡터 next/prev + wrap 단일화** — 3곳 중복, 버그 위험 최대  
2. **채널 상수 + wrap 헬퍼** — 저비용·`+99` 의도 명확화  
3. **키 테이블 디스패치** — OCP  
4. **클래스 분리 + `cout` 정리** — SRP  
5. **`.cpp` 분리, int 내부 표현** — 구조 정리

### 개선 방향 한 줄 요약

**단기**: `std::optional` + 공통 `findNeighbor`로 3중 복제 제거, `constexpr` 채널 상수. **중기**: 키 핸들러 테이블·네비 `variant`/Strategy. **장기**: `DigitInput` / `FavoriteStore` / `ChannelNavigator` 분리. 향후 `updateQuality()`를 넣을 때는 **별도 Policy 클래스**로 두고 `TVController`에 로직을 넣지 않는 것이 좋습니다.

상세 근거·C++17 코드 스케치·라인 참조는 `docs/code_quality_report.md`를 참고하세요.
